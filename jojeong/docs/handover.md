## 4. 사이트 개발·배포 (한 도편수 → 강 어사)

### 4-1. 순서

1. `claude/new-session-espw4a`에서 새 브랜치를 딴다.
2. 고치고 `npm run lint` · `npm run build`(작업 폴더 `jojeong/`). 화면은 Playwright로 캡처해 보여 준다.
3. 커밋 끝에 이 두 줄:
   ```
   Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
   Claude-Session: https://claude.ai/code/<그 방 세션 id>
   ```
4. 푸시(네트워크 실패면 2·4·8·16초 재시도) → PR(base `claude/new-session-espw4a`). `gh`가 없는 방이면 GitHub MCP 도구(`create_pull_request`, `merge_pull_request`)로 한다.
5. **손님이 보는 화면이 바뀌면 결재함에 먼저 올리고, 대표님이 "올려"라고 해야 머지한다.**
6. 머지가 "Base branch was modified"로 막히면 base를 PR 브랜치에 merge해서 다시 푸시하고 재시도.
7. 머지 뒤 라이브(https://www.hundosaju.com)에서 확인한다(아래 4-3). 결과 보고는 `team.md` 형식(무엇·전후·어디서 확인·남은 것).

### 4-3. 라이브 확인 요령

- Playwright 브라우저 UA는 `HeadlessChrome check`로 둔다(관리자 통계에서 구분하려고).
- 팝업(`[role=dialog]`)이 클릭을 막으면 `evaluate`로 지우고 확인한다.
- 통계 이벤트가 나가는지는 `sendBeacon` 본문을 못 읽으니, 페이지 응답(RSC)에 이벤트 이름(예: `sinsal_open`)이 들어 있는지로 확인한다.
- 로컬 서버를 끌 때는 `ps -eo pid,args | grep next-server`로 PID를 찾아 그 번호만 끈다. `pkill -f` 금지. `rm -rf`에 와일드카드 금지.
