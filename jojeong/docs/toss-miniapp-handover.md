# 토스 미니앱 인수인계서 (2026-11-10)

다른 계정, 다른 세션에서 토스 미니앱(앱인토스) 일을 이어받기 위한 문서다. 이 문서만 읽고 바로 이어갈 수 있게 적었다.

## 0. 한 줄 요약

미니앱 3개를 만들었다. **① 훈도사주(결제), ② 내 사주 속 신살 찾기(광고)는 코드가 본선에 있고 콘솔 등록과 출시 절차만 남았다.** **③ 내 사주 동네(명당 지도)는 시제품까지 만들고 멈췄다.** 대표님이 "지명 한자 점수는 설득력 없다"고 해서 빼기로 했고, 대신 넣을 팔택과 지형 데이터는 아직 없다.

## 2. ① 훈도사주 (`hundo-toss/`)

자세한 내용은 `hundo-toss/README.md`에 있다.

| 화면 | 내용 |
|---|---|
| 생일 입력 | 사이트와 같은 규칙 (`jojeong/lib/personForm.ts`) |
| 오늘 | 점수와 가장 좋은 쪽은 무료. 자세한 풀이는 보상형 광고 1회로 그날 내내 열림 |
| 신년운세 | 판정, 달마다 흐름 (무료) → 보고서로 연결 |
| 보고서 | 인앱 결제 sku `hundo_yeonun` 1,900원 / `hundo_pyeongsaeng` 2,900원 / `hundo_ny_set` 3,900원 |
| 내 보고서 | 이 토스 계정으로 산 것. 환불된 것은 빠짐 |

**결제 흐름**: `IAP.createOneTimePurchaseOrder` → `POST {사이트}/api/toss/grant` (토스에 주문 확인 후 사이트 주문 생성, 같은 주문은 한 번만). 미결 주문은 `IAP.getPendingOrders`로 다시 열고, 환불은 `IAP.getCompletedOrRefundedOrders` → `POST /api/toss/refund`.

**출시 전에 할 일 (대표님 몫이 대부분)**
1. 앱인토스 콘솔에 미니앱 만들기 (이름 = `hundo-saju`), 인앱 결제 상품 3개 등록 (sku가 위와 정확히 같아야 함)
2. 인앱 광고 신청 → 보상형 광고 그룹 ID를 `VITE_AD_REWARDED`에
3. mTLS 인증서와 키 발급 → Vercel 환경 변수 `TOSS_AIT_CERT`, `TOSS_AIT_KEY` (키는 Vercel에만, 대화에 붙여 넣지 않기)
4. 샌드박스 첫 결제로 **주문 상태 응답 값 확인**. `jojeong/lib/tossApps.ts`는 `PAYMENT_COMPLETED, PURCHASED, COMPLETED, PAID, DONE, SUCCESS`일 때만 지급한다. 다른 값이면 Vercel 로그에 `toss order not paid`와 원문이 남으니 그 값을 목록에 더한다
5. `npm run build` → `npm run deploy` (콘솔 API 키 필요)

**운영 의무 (유저 피해 대응 정책, 2026-11-21 시행)**: 콘솔 문의를 매일 확인, 환불과 문의는 **받은 날부터 7영업일 안에** 처리 (넘기면 토스가 대신 환불하고 정산금에서 뺀다). 미니앱을 종료하면 서버의 토스 익명 키(`toss:user:*`)를 지운다.

## 5. 대표님과 일하는 규칙 (꼭 지킬 것)

- **한국어 해요체로만** 답한다. 결론 먼저, 표 활용, 끝에 `🧾 토큰: 약 n`
- 손님에게 보이는 변경은 대표님 승인 ("올려", "ㄱㄱ") 뒤에 합친다
- 비밀 키는 Vercel에만. 대화에 붙여 넣지 않는다. **생년월일은 저장하지 않는다**
- 글 규칙: "·"와 "—" 쓰지 않기, 숫자는 "100명 중 n명"처럼 비율로만 (25만, 1950년부터 같은 표현 금지), 손님 화면에 출처 쓰지 않기, 단정하지 않기, "짐승" 대신 "동물"
- 허용 목록에 웹사이트를 추가해야 하면 **주소만 한 칸에 모아서** 복사하기 쉽게 준다
- 봇 차단이나 Cloudflare를 우회하지 않는다. User-Agent를 속이지 않는다
- git: `/home/user/wook`에서 `git reset --hard` 금지. 브랜치 작업은 별도 워크트리에서, 본선은 `claude/new-session-espw4a`, PR은 GitHub MCP로 열고 합친다
